# PRD: 文章管理模組（Article Management）

## 1. 產品願景

提供一套後台文章管理介面，讓內容營運者能高效地瀏覽、篩選、編輯、審核及發布 AI 產出的運動新聞文章。本模組是新聞管線（News Pipeline）的下游消費端，負責「管線產出後」到「正式上線」之間的所有人工介入操作。

### 解決的核心問題

- **批次管理效率**：AI 管線每日產出大量文章，需要高效的批次瀏覽與操作能力
- **品質把關**：自動審稿後仍需人工複查，需要便捷的內容檢視與編輯流程
- **發布控制**：營運者需要靈活的即時發布與排程發布能力，包含多渠道選擇
- **溯源需求**：每篇 AI 文章需追溯原始素材來源，確保內容可查證

### 與 News Pipeline 的關係

本模組與 `prd-news-pipeline.md` 定義的新聞管線系統互補：
- **管線系統**負責爬取、規劃、產文、自動審稿
- **文章管理**負責人工瀏覽、編輯、手動審核、發布決策
- 兩者共用 `generated_articles` 資料表，管線寫入、文章管理讀取與更新

## 2. 目標用戶

### 主要受眾

| 角色 | 使用頻率 | 核心需求 |
|------|---------|---------|
| **內容營運者**（後台管理員） | 每日多次 | 快速瀏覽 AI 產出文章、篩選特定狀態/分類、批次發布或刪除 |
| **總編輯**（品質負責人） | 每日 | 審核文章品質、檢視 AI 審稿結果、編輯修改內容 |

### Persona

**小美 -- 內容營運者**
- 每天早上檢查 AI 管線產出的新文章
- 需要快速判斷哪些文章可以直接發布、哪些需要修改
- 痛點：文章量大時逐篇操作太慢，需要批次處理能力
- 期望：一眼看到文章狀態，幾次點擊完成發布

**阿強 -- 總編輯**
- 抽查 AI 審稿標記為 rejected 的文章，判斷是否值得修改後發布
- 需要查看審稿評分細項和原因
- 痛點：需要同時看到 AI 產文和原始素材，才能判斷品質
- 期望：在同一個頁面完成閱讀、比對、編輯、發布

## 4. 功能範圍

### 做什麼（In Scope）

#### 4.1 文章列表頁

- **分頁瀏覽**：支援可調整每頁顯示數量（預設 20 篇），含頁碼跳轉
- **狀態篩選**：Tab 切換全部/未發布（draft）/排程中（scheduled）/已發布（published）
- **分類篩選**：下拉選單篩選運動分類（NBA、MLB、NPB 等）
- **URL State 同步**：所有篩選條件同步到 URL query string（使用 nuqs），支援書籤和分享
- **響應式設計**：桌面端 Table 佈局 + 手機端 Card 佈局
- **文章資訊展示**：縮圖、標題（含素材數量徽章）、內容預覽、分類色標、寫手名稱、瀏覽數、狀態標籤、建立時間、排程時間

#### 4.2 批次操作

- **多選機制**：Checkbox 逐篇選取 + 全選/取消全選
- **批次發布**：選取多篇文章一次發布，帶確認 Dialog
- **批次刪除**：選取多篇文章一次刪除，帶確認 Dialog（操作不可逆）
- **操作回饋**：loading 狀態、toast 錯誤訊息、操作完成後自動清除選取

#### 4.3 單篇操作（列表頁）

- **快速發布**：單篇即時發布，含 loading spinner
- **快速排程**：展開日期時間選擇器，設定預約發布時間
- **查看詳情**：跳轉到文章詳情頁

#### 4.4 文章詳情頁

- **內容檢視**：完整文章標題、內文（Markdown 渲染）、圖片畫廊
- **內容編輯**：切換編輯模式，修改標題和內文，即時儲存
- **圖片管理**：逐張刪除不適合的圖片
- **發布狀態卡片**：顯示當前發布/排程狀態，支援取消排程
- **發布選項卡片**（僅未發布文章）：
  - 渠道選擇：勾選要發布的社群頻道（Telegram/LINE/Facebook/Twitter）
  - 直接發布：立即發布到選取渠道
  - 排程發布：設定時間後預約發布
- **審稿資訊卡片**：
  - 寫作策略標籤（多源綜合/內容增值/熱門綜合）
  - 審稿狀態（待審/通過/未通過）
  - 9 項評分明細（色標顯示：紅 < 4, 綠 >= 7）
  - Pass/Fail 檢查項（題材/圖片去重 + 有圖片）
  - 平均分數
  - 審查意見文字
  - 審查時間
- **原始素材卡片**：展示 AI 產文參考的 raw_articles（來源、標題、內容、連結）
- **引用來源卡片**：展示 cited_sources（類型、標題、URL）

#### 4.5 管線觸發與規劃管理（列表頁內嵌）

- **產出控制面板**：顯示管線狀態、觸發 Plan 階段
- **規劃列表**：展示 AI 規劃方案，支援選取/刪除/觸發 Produce
- **即時輪詢**：透過 polling 追蹤管線任務進度

#### 4.6 API 層

- **GET /api/articles/generated**：分頁查詢文章列表，支援 status/category 篩選
- **GET /api/articles/generated/[id]**：取得單篇文章詳情 + 關聯原始素材
- **PATCH /api/articles/generated/[id]**：更新文章（編輯內容/發布/排程/圖片管理）
- **POST /api/articles/generated/batch**：批次操作（publish/delete）
- **GET /api/articles/generated/review**：審稿佇列（pending/history）
- **PATCH /api/articles/generated/review**：更新審稿狀態（approved/rejected + reason）
- **GET /api/articles/raw**：原始新聞素材列表

#### 4.7 發布邏輯

- **統一發布函式**：所有發布行為經由 `publishArticle()` 統一處理
- **發布前檢查**：文章必須通過 AI 審查（review_status = approved）且有圖片
- **封面圖去重**：發布前自動檢查 500 篇已發布文章，重複封面自動遞補
- **SSRF 防護**：圖片 URL 過濾內網地址，僅允許 HTTPS
- **多渠道並行發布**：同時推送到所有選取（或全部啟用）的社群頻道
- **快取失效**：發布/刪除後自動 revalidate 前台頁面（首頁、分類頁、文章頁、寫手頁、RSS）

### 不做什麼（Out of Scope）

- **全文搜尋**：目前不支援文章標題或內文關鍵字搜尋
- **文章版本歷史**：不記錄編輯歷史，無法還原到先前版本
- **拖曳排序**：文章順序固定按建立時間降序
- **多人協作編輯**：不支援同時編輯衝突偵測
- **文章草稿自動儲存**：編輯中不自動儲存，需手動點擊儲存
- **進階統計分析**：不提供文章表現分析儀表板（瀏覽數趨勢等）
- **匯出功能**：不支援匯出文章為 CSV/Excel

## 7. 行銷信號判斷

### SEO 信號

- 此模組為後台管理介面（`/admin/articles`），受 NextAuth 認證保護
- **不影響 SEO**：後台頁面不被搜尋引擎索引
- 發布動作觸發前台頁面 revalidate，間接影響 SEO 內容更新速度

### 文案/CRO 信號

- 不適用：純後台操作介面，無面向終端用戶的轉換流程

### 行銷調度建議

- 無需額外行銷調度。發布後的 SEO 效果由 News Pipeline PRD 覆蓋。

## 8. 風險與假設

### 假設

- 營運者每日主動進入後台檢查文章的頻率足夠（至少每日一次）
- AI 審稿通過的文章品質足夠高，大部分可直接發布不需人工編輯
- 批次操作的文章數量不會超過單頁顯示上限（最大 100 篇/頁）
- 所有發布渠道的 API 回應時間在可接受範圍內（< 10 秒）

### 風險

| 風險 | 影響 | 緩解措施 |
|------|------|---------|
| 批次發布大量文章時 API 逐篇串行處理較慢 | 操作等待時間長 | 批次發布採串行確保封面圖去重正確，可加 progress 提示 |
| 編輯中意外關閉瀏覽器導致未儲存的修改丟失 | 編輯內容遺失 | 目前無自動儲存，可考慮加 beforeunload 提醒 |
| 多人同時編輯同一篇文章造成覆蓋 | 最後儲存者覆蓋前者修改 | 目前為單人操作場景，多人時需加樂觀鎖 |
| 發布渠道 API 部分失敗 | 文章已標記 published 但部分渠道未發送 | publishArticle 已記錄各渠道錯誤，可在後台顯示警告 |
| 大量文章累積未處理 | 列表頁效能下降 | 分頁機制 + DB index 已覆蓋 |

## 9. 資料模型概覽

### 核心資料表

| 表名 | 用途 | 本模組操作 |
|------|------|-----------|
| `generated_articles` | AI 產出文章 | 讀取列表、更新內容/狀態/排程/圖片 |
| `raw_articles` | 原始爬取素材 | 唯讀查詢（文章詳情頁溯源） |
| `writer_personas` | 寫手人設 | 唯讀 JOIN（顯示寫手名稱） |
| `publish_channels` | 發布渠道設定 | 唯讀查詢（渠道選擇） |

### 文章狀態流

```
draft (未發布)
  ├── 設定 scheduled_at → 排程中（仍為 draft，但有 scheduled_at）
  │     └── 取消排程 → draft (清除 scheduled_at)
  └── 發布 → published (設定 published_at)
```

### 審稿狀態流

```
pending (待審) → approved (通過) → 可發布
                → rejected (未通過) → 可在後台編輯後重新評估
```
