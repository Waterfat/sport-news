# PRD: 新聞管線系統（News Pipeline）

## 1. 產品願景

提供一套自動化的運動新聞內容生產管線，從多來源爬取即時賽事資訊，經 AI 三階段處理（規劃→產文→審稿），最終自動發布到多社群渠道。目標是以最少人力介入，持續產出高品質、不重複的運動新聞內容。

### 解決的核心問題

- **內容產出效率**：人工撰寫運動新聞耗時且無法 24 小時覆蓋
- **多源整合**：單一來源資訊不夠全面，需要整合多個新聞源
- **品質一致性**：人工產出品質不穩定，需要標準化的審稿流程
- **多渠道分發**：手動發布到多個社群平台耗時且易遺漏

## 2. 目標用戶

### 主要受眾

| 角色 | 使用頻率 | 需求 |
|------|---------|------|
| **內容營運者**（後台管理員） | 每日 | 監控管線狀態、審核/修改 AI 產出、管理爬蟲來源 |
| **一般讀者**（前台訪客） | 每日多次 | 閱讀最新運動新聞、獲取賽事快報 |
| **社群訂閱者**（Telegram/Line/Facebook/Twitter） | 被動接收 | 即時收到新發布的文章推播 |

### Persona

**小明 — 內容營運者**
- 非技術背景，需要直覺式的後台操作
- 痛點：手動爬新聞、改寫、發布到多個社群太花時間
- 期望：系統自動跑完全流程，只需偶爾檢查品質

### 設計策略傾向

極簡自動化 — 管線盡可能自動運作，僅在異常時需要人工介入。

## 4. 功能範圍

### 做什麼（In Scope）

#### 4.1 爬蟲子系統
- **多來源支援**：ESPN、ETtoday、Yahoo Sports、通用 HTML 爬蟲
- **球種過濾**：根據 sport_settings 啟用的球種過濾文章
- **URL 去重**：已爬過的文章不重複儲存
- **圖片下載**：可選擇性下載文章圖片到 Supabase Storage
- **定時排程**：透過 Vercel Cron 或外部觸發 `/api/cron/crawl`

#### 4.2 AI 三階段管線
- **規劃階段（Plan Generator）**
  - 讀取 12 小時內未處理素材
  - 按寫手專長分組
  - Claude AI 分析去重、合併同一事件
  - 標題與已發布文章去重（14 天窗口）
  - 每寫手最多處理 20 篇素材
- **產文階段（Local Rewriter）**
  - 兩種模式：官方戰報（正式新聞）+ 專欄作家（個人觀點）
  - 根據寫手 style_prompt 調整語氣
  - 自動收集圖片（最多 5 張）和提取標籤
  - 記錄引用來源（cited_sources）
- **審稿階段（Editor in Chief）**
  - 9 項審查：標題/內容/事實/品牌/SEO 品質（1-10 分）+ 題材/圖片去重 + 有圖片（pass/fail）
  - 通過標準：平均 ≥ 6 分、無任何項 < 4 分、三項 check 全 pass
  - 通過自動發布，未通過標記 rejected

#### 4.3 任務監聽與自動化
- **Supabase Realtime 監聽**：即時偵測新任務
- **三階段自動接力**：plan → produce → review
- **自動管線**：素材累積到門檻自動觸發全流程
- **防禦機制**：單任務鎖、30 分鐘超時、漏接補查

#### 4.4 多渠道發布
- **支援渠道**：Telegram、LINE、Facebook、Twitter/X
- **統一發布 API**：`publishArticle()` 並行發布到所有啟用渠道
- **封面圖去重**：自動避免與已發布文章使用相同封面
- **SSRF 防護**：過濾非 HTTPS 和內網 URL
- **預約發布**：支援設定 `scheduled_at` 時間

#### 4.5 管線監控（後台）
- Pipeline 狀態頁面：查看所有任務進度
- 手動觸發各階段
- 查看審稿結果和拒絕原因

### 不做什麼（Out of Scope）

- **即時推播通知**：目前為定時批次發布，不做 WebSocket 即時推播
- **使用者互動回饋**：讀者對 AI 產文的品質回饋機制
- **A/B 測試**：不同標題/內容版本的效果測試
- **付費內容**：所有內容免費公開
- **影片爬取/處理**：僅處理文字和圖片

## 7. 行銷信號判斷

### SEO 信號
- ✅ 有 public route：文章詳情頁 `/news/[slug]` 可被搜尋引擎索引
- ✅ 包含可索引內容：AI 產出的運動新聞文章
- **建議**：文章頁面已有 SEO meta tags 和 JSON-LD，持續監控即可

### 文案/CRO 信號
- ⬜ 不適用：管線為後端自動化系統，無前端 CTA 或轉換流程

### 行銷調度建議
- Phase 5 部署後建議跑 `seo-audit`，確認文章頁面 SEO 結構正確

## 8. 風險與假設

### 假設
- ESPN/ETtoday/Yahoo 等新聞源的網站結構不會頻繁變動
- Claude API 的回應品質穩定且符合品牌調性
- Supabase Realtime 連線穩定，漏接機率低
- 社群平台 API 限制（rate limit）不會影響批次發布

### 風險
| 風險 | 影響 | 緩解措施 |
|------|------|---------|
| 新聞源網站改版 | 爬蟲失效 | 通用爬蟲 + 錯誤告警 |
| Claude API 費用增加 | 營運成本上升 | 素材上限控制（MAX 20） |
| AI 產出事實錯誤 | 品牌信譽受損 | Editor-in-chief 9 項審查 |
| Listener 意外停止 | 管線中斷 | 30 秒心跳補查 + 手動重啟 |
| 社群 API rate limit | 部分發布失敗 | 並行發布 + 錯誤重試 |

## 10. 資料表概覽

| 表名 | 用途 | 關鍵狀態流 |
|------|------|-----------|
| `raw_articles` | 爬蟲原始素材 | `is_processed: false → true` |
| `rewrite_plans` | AI 規劃方案 | 建立後由 produce 消費 |
| `rewrite_tasks` | 管線任務追蹤 | `pending → running → completed/failed` |
| `generated_articles` | AI 產出文章 | `draft/pending → draft/approved → published` |
| `writer_personas` | 寫手設定 | `is_active` 控制是否參與 |
| `crawl_sources` | 爬蟲來源 | `is_active` 控制是否爬取 |
| `publish_channels` | 發布渠道 | `is_active` 控制是否發布 |
| `automation_settings` | 自動化設定 | `is_auto_mode` 開關 |
